# TRAPO ICE case (case_93)

This directory contains the compiler-failure reproduction case reported in the
paper. During the 10,000-call evaluation of the TRAPO configuration, one
generated program caused a genuine GCC internal compiler error (ICE). The
program was reduced to two lines and reproduced on two independent GCC builds;
clang 13 produces a regular diagnostic.

| Verified ICE count | 1 (the verified ICE in the evaluation) |

The reduced source is the exact original file:

```cpp
template<class T> struct C { auto g() -> decltype([](auto&x){return x;}) { return [](auto&x){return x;}; } };
C<int> o; auto l = o.g();
```

## 2. How the ICE occurs

The program is ill-formed: the lambda returned by the function body has a
different closure type from the lambda named in the trailing return type.
GCC should report a type-mismatch diagnostic. Instead, while formatting that
diagnostic, the C++ front end substitutes the lambda expression again, the
diagnostic machinery is re-entered, and GCC aborts with:

```text
internal compiler error: error reporting routines re-entered.
```

The stack includes `tsubst_lambda_expr` (`gcc/cp/pt.cc:20184`),
`dump_template_bindings` (`gcc/cp/error.cc:492`), and
`diagnostic_report_diagnostic` (`gcc/diagnostic.cc:1593`). The first frame in
the instrumented build is `push_template_decl` (`gcc/cp/pt.cc:5865`).

## 4. Reproduce

Requirements: a C++ compiler. The reproduction was verified with the
instrumented GCC 13.1.0 build and stock Ubuntu g++ 11.4.0.

```bash
chmod +x reproduce.sh

# Default: stock or instrumented g++ in PATH, one run
./reproduce.sh

# If the evaluated compiler is available:
CXX=/path/to/GCC-13-COVERAGE/bin/g++ ./reproduce.sh --runs 5

# Cross-version check:
CXX=/usr/bin/g++ ./reproduce.sh --runs 3

# Negative control (clang 13 uses -std=c++2b):
CXX=clang++ STD=c++2b ./reproduce.sh

# Save the diagnostics:
./reproduce.sh --out reproduced_output.txt
```

Expected result on GCC:

```text
internal compiler error: error reporting routines re-entered.
Please submit a full bug report, with preprocessed source if appropriate.
```

Expected result on clang:

```text
error: no viable conversion from returned value of type '(lambda at ...)'
       to function return type 'decltype([](auto &x){ return x; })'
```

## 6. Upstream status

The failure belongs to the same root-cause family as GCC PR c++/124397 and
PR c++/125678:

- **PR c++/124397** — checked online on 2026-10-13 and marked **FIXED**.
  The fix (`r16-8015-g2572ce8`, M. Polacek, committed 2026-03-12) adds an
  `emitting_diagnostic_p()` guard and changes `tsubst_lambda_expr`, which is
  the function on this stack. The fix is likely to cover this case; the local
  test matrix covers GCC 13.1.0 and GCC 11.4.0, with GCC 16 outside the
  matrix.
- **PR c++/125678** — filed 2026-06-09, **UNCONFIRMED**, P3, reported on
  GCC 14.1–14.2. Its trigger differs from this case.

This case uses a class-template member function with a trailing-return-type
lambda that does not match the lambda returned from the body. That trigger
differs from both reports, so it can be reported as an independent reproduction
or as a supplementary case for PR c++/124397.

## 7. Test matrix and scope

1. The instrumented build is GCC 13.1.0 with coverage instrumentation. The same
   program also ICEs on stock, uninstrumented Ubuntu GCC 11.4.0, which places
   the defect in the compiler front end.
2. The local test matrix covers the instrumented GCC 13.1.0 build and stock
   Ubuntu GCC 11.4.0. Later GCC releases were outside the matrix.
3. The instrumented build's `.gcda` output path pointed at an old account and
   printed write warnings. The warnings relate to coverage collection; the ICE
   reproduction is unchanged.
4. The other `CRASH_ICE` label in the same 10,000-call run (`case_6323`)
   corresponds to an ordinary `'cout' is not a member` error; the verified
   count reflects the manual inspection.
5. This report documents a reproducible ICE in the evaluated builds, on the
   same root-cause path as a known upstream report.
6. The archived instrumented-build logs contained absolute `.gcda` output
   paths from the original machine. Those path prefixes were replaced with
   `<GCC_BUILD_DIR>/` for privacy. The ICE diagnostics, stack frames, and exit
   codes are otherwise unmodified.
